# F.AGEN-arr-01.CIFI-1.1 spec del cliente

Al operar en Reino Unido y Suiza, la infraestructura debe ser impecable en términos de soberanía de datos y seguridad. Estamos ante un proyecto de "alta fidelidad" donde la confianza es el producto real que vendes.

Aquí tienes la auditoría técnica y el plan de ignición.

## PILAR 1: IGNICIÓN DEL PROYECTO (MVP)

El objetivo de la Fase 1 es validar el Matching de Operaciones sin construir una plataforma compleja desde cero.

- **MVP Incluye:**
  - Base de datos centralizada de Contactos (KYC básico incluido).
  - Inventario de Oportunidades (Commodities) con buscador por filtros.
  - Sistema de mensajería interna vinculado a "Tickets" de operación.
  - Gestión documental para Compliance (UK/Swiss standards).
- **MVP Excluye:** Automatizaciones de matching por IA, pasarela de pagos compleja, app móvil nativa.
- **Herramientas Google Fase 1:**
  - **Google AppSheet:** Permite crear la aplicación de gestión (el CRM/MLS) sin escribir código, conectada directamente a Google Sheets o Cloud SQL.
  - **Google Workspace (Drive):** Para el almacenamiento de documentos de compliance con permisos granulares.
  - **Looker Studio:** Para visualizar el "pipeline" de operaciones y el inventario disponible de forma profesional.
- **Resultado Real:** Una herramienta operativa en 15-21 días para que tus agentes empiecen a cruzar operaciones y registrar el cumplimiento legal.

## PILAR 2: ARQUITECTURA DE HOSTING Y DATOS

Dado que el presupuesto es bajo (< 50€/mes), aprovecharemos el free tier de Google Cloud y el coste por usuario de Workspace.

### Tabla de Arquitectura Recomendada

| Capa | Herramienta | Función | Límite Plan Gratuito | Activación de Coste |
|---|---|---|---|---|
| Identidad | Google Workspace | Email profesional y Auth | 14 días prueba | ~5.75€/ usuario/ mes |
| Backend/ Lógica | AppSheet | El CRM/MLS (Core) | 10 usuarios (prototipo) | ~5€ o 10€/ usuario/ mes\* |
| Base de Datos | Google Sheets/ Cloud SQL | Almacén de registros | Sheets (Gratis) | Cloud SQL: ~8€/mes (micro) |
| Hosting Web | Firebase Hosting | Funnel de captación (SEO) | 10GB almacenamiento | Tras exceder transferencia |
| Mensajería | AppSheet Chat/Notif. | Comunicación interna | Incluido en AppSheet | N/A |

**Nota sobre Pagos:** Google no cubre la capa de pagos de forma óptima. La alternativa recomendada es Stripe porque permite crear "Escrow" o pagos condicionados, vitales en trading de commodities. Se integra vía API con AppSheet o mediante Zapier/Make.

\*Si tienes menos de 5 agentes, AppSheet + Workspace se mantiene dentro de tus 50€/mes con margen de sobra.

## PILAR 3: NAMING Y GESTIÓN DE DOMINIOS

En el sector financiero de UK/Suiza, la extensión del dominio es un factor de autoridad.

### Análisis de Extensiones

| Extensión | Ideal para | Ventaja Principal | Desventaja Principal |
|---|---|---|---|
| .com | Negocio Global | El estándar de oro en confianza. | Muy difícil encontrar nombres cortos disponibles. |
| .ch / .co.uk | Mercado local | Máxima confianza en Suiza o UK. | Limita la percepción de "broker global". |
| .capital / .finance [?] | Nicho financiero | Posicionamiento de marca directo. | Puede ser visto como "menos serio" que un .com. |
| .solutions | B2B / SaaS | Útil si te enfocas en el software. | Palabra larga, difícil de recordar. |

### Arquitectura de Subdominios (Escalabilidad)

| Subdominio | Función | Activar en Fase |
|---|---|---|
| portal. | Acceso de agentes al CRM | Fase 1 |
| www. | Web de captación (Funnel) | Fase 2 |
| data. | Documentación de cumplimiento | Fase 1 |

**Recomendación de Registro:** Utilizar Cloudflare Registrar. Es el más económico (precio de coste) y ofrece la mejor capa de seguridad (WAF) gratuita para proteger tu base de datos de ataques básicos.

## PILAR 4: HOJA DE RUTA WEB3 (OPCIONAL - FASE 3)

Este proyecto califica para Web3 debido a la naturaleza de los Commodities.

1. **Tokenización de Activos (RWA):** En el futuro, las "oportunidades" de commodities pueden representarse como tokens para facilitar la división de comisiones o la propiedad fraccionada de contratos.
2. **Smart Contracts para Compliance:** Automatizar el release de fondos (vía Stripe o Stablecoins) solo cuando ambos lados de la operación hayan subido los documentos validados a la arquitectura de Google.
3. **Transparencia:** Uso de una red como Polygon (bajo coste) para dejar constancia inmutable del cierre de operaciones sin revelar datos sensibles.

## DIAGNÓSTICO FINAL

Tu idea es viable con un stack de Google AppSheet + Cloud SQL. Es la forma más barata de tener una herramienta "grado financiero" sin gastar miles en desarrollo a medida.
